网络盈利状况: sopr (花费输出利润率)，判断市场整体是处于盈利还是亏损状态，是关键的支撑/阻力位指标。
长期持有者行为: hodler_net_position_change (HODLer净头寸变化)，观察长期投资者的增持/减持行为。
API方案: 我们可以从 Glassnode 的免费API层级（Tier 1）开始，它提供了对上述关键指标的每日数据的访问权限。

2. 数据源与技术调研

这部分的核心挑战在于如何从浩瀚的互联网信息中，可靠、低延迟地捕获这些非结构化信号。

宏观经济政策:
来源: 美联储 (Federal Reserve) 官网公告、欧洲央行 (ECB) 会议纪要、主要财经新闻社（路透、彭博）的头条。
技术方案: 可以通过脚本定期爬取美联储官网的“新闻稿”页面，或者利用更通用的新闻API（如 NewsAPI）并设置关键词过滤（如 "FOMC", "interest rate", "inflation"）。
关键人物发言 (推特):
来源: Twitter (X) API。
技术方案: Twitter API 的使用目前有一定限制和成本。一个可行的方案是：
初期: 识别少数几个影响力最大的人物（如马斯克、部分SEC官员等）。可以利用 IFTTT 或 Zapier 等自动化工具，将他们的新推文通过 Webhook 推送到我们自己的服务器或一个私有频道，再由脚本进行处理。这是一种低成本的启动方式。
长期: 申请付费的 Twitter API 访问权限，构建一个专门的流式监听服务，实时捕捉和处理相关推文。
公司/组织动态:
来源: 公司官方博客、SEC 文件、主流加密媒体（如 The Block, CoinDesk）。
技术方案: 这部分信息可以被我们用于新闻情绪分析的 CryptoPanic API 或通用新闻API所覆盖。关键在于建立一个实体和事件的关键词库（如 "MicroStrategy", "Tesla", "buys Bitcoin", "ETF approval"）。
3. 实施计划

这个阶段的核心是构建一个统一的 “事件收割机 (Event Harvester)” 和一个 高级自然语言处理 (NLP) 管道。

创建事件收割机 (tools/event_harvester.py):
创建一个独立的、可长期运行的服务。
它将集成多个数据源：新闻API、RSS订阅（如美联储官网）、Webhook（接收推特推送）等。
构建高级NLP处理管道:
收割机获取到原始文本后，将执行比简单“正/负面”更复杂的处理：
实体识别 (NER): 识别出文本中涉及的关键实体，如“埃隆·马斯克”、“SEC”、“比特币”。
事件分类: 将事件归类，例如：宏观政策, 名人发言, 机构采用, 监管动态。
影响评估 (高级): 训练一个分类模型，初步评估该事件对市场的潜在影响级别（高、中、低）。
结构化存储:
将处理后的结构化信息（时间戳, 事件类型, 关键实体, 摘要, 影响评级）存入本地数据库（如 SQLite）。
特征工程 (features/feature_engineering.py):
创建新的 _add_event_features 函数。
它将从本地事件数据库中读取数据，并生成新的特征列，例如：
离上一次美联储公告过去了多久 (时间差特征)
过去1小时内是否有马斯克发言 (0/1布尔特征)
过去24小时正面监管新闻计数 (计数特征)
